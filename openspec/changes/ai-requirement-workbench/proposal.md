## Why

当前 AI 辅助编程工具（如 Cursor、Copilot）聚焦于"写代码"环节，但需求分析阶段仍然是空白。大量有想法但缺乏编程知识的人，无法将自己的模糊构想转化为结构化的软件需求。他们面临的核心障碍是：遇到不懂的概念就要停下来搜索，注意力在多个窗口间频繁切换，最终想法依然零散、无法交付。

本产品旨在打造一款**AI 需求分析工作台**，让用户通过"超文本式"的树状知识探索，在 AI 的持续引导下，将模糊想法一步步拆解为可交付的 IEEE 830 标准软件设计文档（SDD）。

## What Changes

这是一个全新项目，从零搭建，包含以下核心能力：

- **超文本交互系统**：AI 自动识别文本中的技术名词并以虚下划线标记，用户点击即可弹出解释窗口；用户手动划选短文本→高亮→点击→创建新窗口；划选长文本→高亮→在当前窗口以引用块形式插入，供追问使用。全程无按钮、无悬浮元素。
- **多窗口堆叠管理**：窗口以卡片形式堆叠，新窗口正放，旧窗口自动倾斜变灰退后；输入框固定底部不动；支持拖拽、缩放、最小化；无窗口数量上限。
- **知识树结构**：每个窗口自动成为树上的一个节点，父子关系由"划词创建"绑定；侧边栏以树形展示所有节点，区分"打开中"与"已关闭（可恢复）"；删除节点时子节点提升至父级；节点支持面包屑导航。
- **画布视图**：一键切换至可交互的无限画布模式，所有节点平铺展示，支持拖拽重排、双击打开、关联线标注。
- **AI 对话引擎**：基于 LangGraph 的多轮对话管理，每个窗口独立的 graph 实例，支持流式响应、Markdown 渲染、代码高亮。
- **SDD 生成器**：遍历知识树，自动将节点映射到 IEEE 830 标准章节，输出结构化文档；用户可自定义映射规则和编号样式。
- **AI 质检 Agent**：在 SDD 生成前执行完整性、一致性、可测试性、EARS 合规率检查，输出质检报告，用户可选择修复后继续或跳过。
- **AI 持续建议面板**：侧边栏常驻建议面板，AI 在后台持续分析知识树状态，检测遗漏维度、冲突方案、悬空节点，主动给出建议。
- **本地优先存储**：MySQL 存储永久数据（会话、消息、树结构），Redis 缓存活跃窗口状态和堆叠顺序。
- **单用户模式**：当前仅支持单机/单用户，不涉及多用户、账户、权限或云端同步。

## Capabilities

### New Capabilities

- `hypertext-interaction`: 超文本交互系统 — 自动名词识别（虚下划线）、划选高亮点击、引用追问、无需按钮的交互范式
- `window-stack`: 窗口堆叠管理 — 卡片式堆叠、倾斜变灰动画、拖拽缩放、无上限窗口、输入框固定底部
- `knowledge-tree`: 知识树结构 — 父子节点绑定、侧边栏树形导航、节点状态管理、级联提升删除、面包屑路径
- `canvas-view`: 画布视图 — 无限画布、节点平铺、拖拽重排、关联线、一键切换
- `ai-chat-engine`: AI 对话引擎 — 基于 LangGraph 的多轮对话、独立窗口上下文、流式响应、Markdown/代码渲染
- `sdd-generation`: SDD 文档生成 — IEEE 830 标准映射、自定义映射规则、EARS 格式支持、编号样式选择
- `quality-agent`: AI 质检 Agent — 完整性/一致性/可测试性/EARS 合规率检查、质检报告、修复建议
- `ai-suggestion-panel`: AI 持续建议 — 侧边栏建议面板、实时分析知识树状态、主动推荐探索方向
- `data-persistence`: 数据持久化 — MySQL 永久存储、Redis 缓存、单用户本地优先模式

### Modified Capabilities

无。这是一个全新项目，不修改现有能力。

## Impact

- **技术栈**: Vue 3 (前端) + FastAPI (后端) + LangGraph (AI 引擎) + MySQL (永久存储) + Redis (缓存)
- **新项目**: 无现有代码库需修改，全部从零搭建
- **依赖**: AI 大模型 API（OpenAI/Claude/DeepSeek），需用户自行配置 API Key；用户需自建反向代理解决 CORS 问题
- **部署**: 单用户自部署模式，不提供 SaaS 云端服务
